# luogu-import v1.1.0

仓库：https://github.com/JiangWanZhengChouYv/luogu-import

HydroOJ 的洛谷插件：**拉题 → 多语言题面 → 本地样例评测 → 提交到洛谷 → 用 AC 代码反算极限测试点**。

- 适配：HydroOJ **5.x**（`@hydrooj/register` + Node 22）
- 依赖：无额外 npm 依赖（只用 `hydrooj` 自带的导出）

## 功能

| 功能 | 说明 |
| --- | --- |
| 单题 / 多题 / 区间导入 | `P1001`、`P1001,P1002`、`P1000-P1010` |
| 按列表筛选导入 | 关键词、难度、标签、页码，来源可选 `P/B/CF/SP/AT/UVA` |
| 全量拉取 | 按来源逐页遍历到空页，断点续跑，支持暂停 / 继续 / 取消 |
| 空号探测 | 全量跑完后对题号区间内未收录的号做 HEAD 探测，存在的补抓 |
| 多语言题面 | 洛谷 `translations` → Hydro `problem.statement`（`zh.md` / `en.md` …），`?lang=` 切换 |
| 登录态 | 后台填 `_uid` + `__client_id`，AES-256-GCM 加密存 Mongo，日志 / 接口只暴露长度 |
| 匿名降级 | 未配置登录时仍可抓公开题；全量模式默认要求登录，页面可显式勾选匿名 |
| 提交到洛谷 | 题目页侧栏 / 在线编程工具栏按钮，支持验证码弹图重提 |
| 提交即本地评测 | 同一份代码同时交洛谷并跑一遍本地测试点，结果并列展示 |
| 反算测试点 | 洛谷 AC 后把代码存为标程，按题面数据范围生成极限规模测试点 |
| 范围识别模型 | 中英双语，从「数据范围」段自动认出规模参数（测试集 96%），中文覆盖 64% |
| 用户独立账号 | `luogu.accounts` 按 Hydro uid 存各自的洛谷提交账号，不串号 |

## 安装

1. 把本目录复制到 Hydro 实例的 addons 目录（Docker 部署通常是挂载点）：

   ```bash
   cp -r luogu-import /path/to/hydro/addons/
   ```

2. 在 `addon.json` 里注册：

   ```json
   ["@hydrooj/ui-default", "/root/.hydro/addons/luogu-import"]
   ```

3. 重启 backend（Docker）：

   ```bash
   docker compose restart oj-backend
   ```

4. 用管理员登录，进入 **控制面板 → 洛谷题目导入**（`/manage/luogu`）。

> 插件会覆盖 `templates/partials/{nav,problem_sidebar_normal}.html`。升级 `@hydrooj/ui-default` 后需要同步比对这两个文件，否则可能丢原生菜单项。

### 对已有站点的影响

本插件按「不改变别人站点行为」设计，默认只**新增**入口，不改动原有内容：

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 顶部导航「评测记录」 | **保留** | 只有把系统设置 `luogu-import.hideRecordNav` 设为 `true` 才会隐藏 |
| 题目侧栏 | 仅追加「提交到 Luogu」 | 只对洛谷题显示，本站原创题不受影响 |
| 在线编程工具栏 | 仅追加「提交到 Luogu」 | 不改原生递交行为 |
| 系统设置 / 站点名 / 公告 | **不写** | 插件不修改这些 |
| 已有题目 | **不动** | 导入时同名题默认跳过，需显式 `overwrite` 才覆盖 |

**验证范围**：Hydro **5.0.7 / 5.1.0**，`@hydrooj/ui-default` **4.58.5 / 4.59.1**，Docker 部署，单域。

**未验证**：其他 `ui-default` 版本、非 Docker 部署、多域站点、中英文之外的 locale。

`problem_sidebar_normal.html` 与 `nav.html` 在这两个版本里逐字相同，所以覆盖不会错位；
但其他版本的模板结构若不同，覆盖会丢掉原生菜单项。症状是题目侧栏少按钮 ——
删除 `templates/partials/{nav,problem_sidebar_normal}.html` 即可回退到「只有后端功能」
（拉题 / 提交接口不受影响，只是题目页没有侧栏按钮）。

题目页判断「是不是洛谷题」只看 `luogu.problems` 的登记，不看题号前缀 ——
否则本站自带的 `P1000` 之类会被误认成洛谷题。若你是从旧版本升级、标记表为空，
可以设 `luogu-import.pidPrefixFallback = true` 临时退回前缀判断。

### 批量删题接口的保护

`POST /manage/luogu/cleanup` 会调用 `ProblemModel.del`，为防止误删：

- 必须显式传 `keep`（不再默认 `P1001`）
- 默认 `dryRun: true`，只返回将要删除的清单
- 真删需要同时传 `dryRun: false` 与 `confirm: "DELETE"`
- **只处理 `luogu.problems` 里登记过的题**（即本插件真的导入过的），本站原有题目不会被删
  - 早期版本按题号形态判断，会把 Hydro 自带的演示题 `P1000` 也算进去，已修正

## 配置

### 拉题账号（管理员，全站共享）

`/manage/luogu` 的「洛谷账号」区填写：

- `_uid`：洛谷用户数字 ID
- `__client_id`：浏览器 Cookie 里的值（长度不固定，可能 36 或 48 位）

保存后点「测试登录」应显示 `已登录：<用户名>`。`__client_id` 加密后存 `luogu.config`，密钥在 `data/backend/luogu.key`（权限 600）。

- **删掉 `data/` 后必须重新配置登录态**（密钥随数据目录一起重建）。
- 密钥文件不要提交、不要外发。

### 提交账号（每个用户）

导航「第三方账号」→ `/luogu/account` 绑定自己的 `_uid` / `__client_id`。未绑定的用户提交时按约定回退到全站账号，页面会明确标注。

## 使用

### 后台导入

`/manage/luogu` 支持：

- 题号：`P1001`、`P1001,P1002`、`P1000-P1010`
- 列表：关键词 / 难度 / 标签 / 页码（先点「获取标签」）
- 全量：勾选来源 + 题数上限（0 = 不限）+ 限速（默认 1500ms）
- 测试点来源：第一组样例 / 全部样例 / 不生成
- 覆盖已有题目、隐藏题目、目标域

全量任务可暂停 / 继续 / 取消，backend 重启后自动从断点续跑。

### CLI（当前不可用，用后台页面代替）

```bash
# 期望的用法（Hydro 5.0.7 / 5.1.0 上会报 "Script luoguImport not found."）
hydrooj cli script luoguImport '{"pids":["P1001"]}'
```

**为什么不能用**：Hydro 的 CLI 在 addon 的 `apply()` 执行完成之前就去查
`global.Hydro.script`，所以插件注册的脚本必然查不到（实测：报错之后
`Registry` 里才出现 `luoguImport`）。这是上游加载时序问题，不是插件配置错误。

请改用**控制面板 → 洛谷题目导入**（`/manage/luogu`），功能完全一致且能看实时进度。

### 提交

- 题目页侧栏「提交到 Luogu」
- 在线编程（scratchpad）工具栏「提交到 Luogu」

提交后结果按 Hydro 原生评测记录表格展示：洛谷行 + `LOCAL` 行。只有验证码才弹窗。

## 反算测试点

洛谷 AC 后自动触发（同一份代码 hash 幂等）：

1. 用内置模型（中英双语）从「提示 / 数据范围 / Constraints」段识别规模参数；模型认不出时退回规则解析 `n`；
2. 按官方样例结构放大到上界（`n 行` / `n m 行` / 单个数 / 行内数组 / 坐标题 / 方格题 n² 填满）；
3. 10 组不同 profile（最小 / 随机 / 升序 / 降序 / 全值域最大），generate 时限取题面 90%；
4. 成功 ≥6 组即写入，失败组自动清理残缺 `.in`。

管理接口：`GET /manage/luogu/oracle/:pid`（看标程 hash 与统计）、`POST {force:true}`（手动重算）、`{scale:N}`（放大规模）。

### 能跑到什么程度

- **规模**：结构能识别 + 题面能解析出 `n` 时，数据到题面上界；否则退化为「只随机值、规模不变」。
- **时间**：不保证接近时限。`O(1)` 或小 `n` 的题（如 A+B、N≤9 的方格）本身就跑不满；插件也不会为了碰时限把正确标程逼到 TLE。
- **内存**：Hydro `generate` 判题器的 std 沙箱写死 256MB，无法造内存压力。
- **强度**：随机极限数据不等于对抗性数据（树/图/字符串的最坏结构仍需专属生成器）。

## 权限

| 路由 | 权限 |
| --- | --- |
| `/manage/luogu*` | `PRIV_EDIT_SYSTEM`（管理员） |
| `/luogu/submit/*`、`/luogu/record/*`、`/luogu/account` | 登录用户 |

所有 POST 都校验 `Referer`（Hydro CSRF）。

## 已知限制

- 洛谷官方测试数据不公开，本地评测基于样例或反算数据，**不等价于洛谷 AC**。
- 洛谷有反爬（302 / C3VK / 验证码），全量拉取务必保留限速；建议 ≥1500ms。
- 提交可能要求图形验证码，需人工输入。
- 结构化输入（树、图、矩阵、字符串）的生成器覆盖有限，识别不了时不会放大规模。
- `generate` 判题器内存沙箱固定 256MB，无法测出内存极限。
